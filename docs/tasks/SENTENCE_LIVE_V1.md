# 1. Product definition

## 1.1 The problem

A learner can chat with the AI all day and still freeze when a real conversation
happens. The app trains conversation, listening reflexes and reading aloud, but it has
no place to collect **the specific sentences a native speaker actually says in a given
situation** and drill them until they come out automatically.

## 1.2 The feature

**Real-life sentences**: user-created topics, each holding a bank of short, everyday
English sentences generated by the learner's own AI provider. Each sentence carries an
English-only meaning and a real-life situation. The learner practices the topic with
spaced repetition: sentences they remember well come back after longer and longer
gaps, sentences they forget come back in ten minutes.

There is **no Vietnamese anywhere in this feature** (and none is added to the app): the
meaning is a plain-English paraphrase, the situation is one short English line.

## 1.3 User journey

```text
Home
  └── Real-life sentences            (topic list; due-count badge on the Home row)
        ├── New topic              (title + optional description, e.g. "meeting someone new")
        ├── Delete topic           (confirm modal; cascades sentences + review log)
        └── Topic screen           (sentence list; default empty)
              ├── Generate new sentence   (choose 1 / 5 / 10)
              │     └── Review modal      (keep all / keep selected / discard)
              ├── Per-sentence TTS        (speaker button on every row)
              ├── Delete sentence
              └── Practice                (enabled at 5+ sentences)
                    └── Practice screen   (due cards only, max 20 per session)
                          ├── dictation card  (new / learning sentences)
                          └── recall card     (review sentences)
```

## 1.4 Confirmed product decisions

These decisions were confirmed by the product owner and are binding for this task list.

| Decision | Choice |
| --- | --- |
| Grading buttons | **Again / Hard / Good / Easy** (FSRS ratings 1–4), true spaced repetition powered by [`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs) |
| Card mix | **Automatic**: dictation for `new`/`learning`/`relearning` sentences, situation-recall for `review` sentences; a Settings toggle can force one mode |
| Typing check | Word-level, case- and punctuation-insensitive, word-level diff shown, grade **pre-suggested** (Good for a clean answer, Again for missing words) and **overridable** by the learner |
| Session | **Due cards only**, maximum 20 per session; a card stays in the session until FSRS graduates it to `review` |
| Study day | A new day starts at **4 a.m. local time** (Anki's rollover), for both `elapsed_days` and review due dates |
| Practice unlock | Topic needs **5 or more sentences** |
| Sentence fields | English `text` + English `meaning` + short real-life `situation` |
| Generation | Count chosen by the user (1 / 5 / 10), existing topic sentences passed to the model, normalized exact-match filter locally, then a keep/discard review modal |
| Icons | `react-native-svg` + `lucide-react-native` |
| Scope | Serverless only, local SQLite, no Django changes |
| Language | No Vietnamese; English-only meaning and situation |

# 2. Technical specification

## 2.1 Local schema (migration version 6)

The sentence tables were introduced in v4/v5. **v6** (`MIGRATION_006` in
`mobile/src/db/migrations.ts`, never edit shipped migrations) rebuilds them for
FSRS and adds the collection config. Legacy rows are preserved; the old
`suspended` state becomes Anki's flag.

`sentences` (v6):

| Column | Meaning |
| --- | --- |
| `state` | FSRS card state: `new` / `learning` / `review` / `relearning` |
| `suspended` | Anki flag (0/1); excluded from sessions but keeps its memory state |
| `stability`, `difficulty` | FSRS memory state (days / 1–10) |
| `elapsed_days`, `scheduled_days`, `learning_steps` | remaining `ts-fsrs` `Card` fields |
| `reps`, `lapses` | review counters |
| `due_at` | ISO instant; review cards are due at the start of the target study day |
| `last_grade`, `last_reviewed_at` | last review |

`sentence_review_log` mirrors Anki's `revlog` so the history can train the FSRS
optimizer: `grade`, `rating` (1–4), `state` **before** the review, `mode`,
`due_at`, `stability`, `difficulty`, `elapsed_days`, `last_elapsed_days`,
`scheduled_days`, `learning_steps`, `review_duration_ms`, `reviewed_at`.

`srs_config` is a single row (`id = 1`): `model_version`, `weights`
(space-separated, empty = package default), `desired_retention`,
`maximum_interval`, `enable_fuzz`, `enable_short_term`, `learning_steps`,
`relearning_steps`, `rollover_hour`, `updated_at`.

Indexes: `idx_sentences_topic_normalized` (unique duplicate key),
`idx_sentences_topic`, `idx_sentences_due`, `idx_sentences_topic_state`,
`idx_sentence_review_log_sentence`, `idx_sentence_review_log_reviewed`.

Notes:

- `normalized_text` is the duplicate key (see 2.4) and is unique per topic.
- A newly generated sentence is immediately due (`due_at` = now) so a fresh topic can
  be practiced at once.
- `suspended` sentences are excluded from every practice session. Nothing in this
  version suspends a sentence, but the flag exists so a future "stop showing me this"
  does not need another migration.

## 2.2 Spaced repetition (pure module: `mobile/src/srs/scheduler.ts`)

Scheduling is delegated to `ts-fsrs` (FSRS-6, the model Anki ships). The adapter
is pure: `reviewSentence(state, grade, now, config)` and
`previewSchedule(state, now, config)` receive the clock and the collection config
and never read storage.

Buttons and ratings:

| Button | `Rating` | Store grade |
| --- | --- | --- |
| Again | `Rating.Again` = 1 | `'again'` |
| Hard | `Rating.Hard` = 2 | `'hard'` |
| Good | `Rating.Good` = 3 | `'good'` |
| Easy | `Rating.Easy` = 4 | `'easy'` |

Defaults (Anki's), stored in `srs_config` and described by `src/srs/config.ts`:

```text
desired_retention    = 0.9
maximum_interval     = 36500 days
enable_fuzz          = true
enable_short_term    = true
learning_steps       = '1m 10m'
relearning_steps     = '10m'
rollover_hour        = 4          (local time)
weights              = package FSRS-6 default; replaced by optimizer output
```

Behaviour with the default steps:

- A new card answered **Again / Hard / Good** enters `learning` due in 1 / 6 / 10
  minutes. A second **Good** graduates it to `review`.
- **Easy** on a new card graduates immediately (about 8 days with default weights;
  fuzz is seeded per card, so the interval shown on the button is the one saved).
- A **review** card is rescheduled by FSRS stability: Again → `relearning` at 10
  minutes and `lapses + 1`; Hard/Good/Easy → `review` with increasing intervals.
- Review intervals are capped by `maximum_interval`; the package keeps
  Hard ≤ Good ≤ Easy, so the cap may be exceeded by the 1-day ordering steps.

Study-day rules (`src/srs/dayBoundary.ts`):

- `elapsed_days` is the number of **local study days** between reviews, where a
  study day starts at `rollover_hour` (4 a.m.). A 2 a.m. review is still the
  previous day; 4:30 a.m. is a new one.
- `ts-fsrs` derives elapsed time from a plain date difference, so the adapter hands
  it a synthetic `last_review` exactly `elapsed_days` days before `now`.
- A graduated card becomes due at the **start** of its target study day (4 a.m.),
  matching Anki's day-number queue; learning/relearning cards keep minute
  timestamps.

The module never touches SQLite; the repository persists the returned state and
log row. Collection helpers (`getSrsConfig`, `saveSrsConfig`,
`listReviewHistoryForOptimization`) live in `src/db/srsConfigStore.ts`.

## 2.3 Practice session (`mobile/src/srs/session.ts`)

`buildPracticeSession(sentences, now, limit = 20)`:

- Include only sentences with `suspended = 0` and `due_at <= now`.
- Order by `due_at` ascending, then `id` ascending.
- Cap at `limit` (20).
- A card leaves the queue only when FSRS graduates it to `review`. While it is
  `learning` or `relearning` it is appended to the end of the session (Anki's
  learn-ahead behaviour), so Again — and the first Good on a new card — brings it
  back until it graduates.

`canPractice(sentenceCount)`:

- `true` when the topic holds **5 or more** sentences.

When nothing is due the practice screen shows an "All caught up" empty state naming the
next due time. There is deliberately **no** "practice ahead" mode: grading a sentence
that is not due would corrupt the schedule.

## 2.4 Duplicate detection (`normalizeSentenceText`)

Used both for the local filter after generation and for the unique index:

1. Lowercase.
2. Expand the common contractions used by the comparison only (`don't → do not`,
   `it's → it is`, `I'm → i am`, `we're → we are`, `can't → cannot`, ...).
3. Replace every character that is not a letter, digit or apostrophe-derived word
   separator with a space.
4. Collapse whitespace and trim.

Two sentences with the same normalized form are duplicates.

## 2.5 AI generation contract (`mobile/src/serverless/sentenceGeneration.ts`)

One completion through the existing registry seam
(`loadServerlessConfig` + `createProviderClient`), the same way
`serverless/speakingPractice.ts` and `serverless/topicGeneration.ts` do it.

System instruction (essence):

```text
You write everyday English sentences for a learner who wants to sound natural in real
life. Write the way people really talk and text, not the way textbooks or exams teach:
prefer common, current slang, idioms, informal wording and abbreviations/initialisms
(ASAP, BTW, FYI, gonna, wanna, ...) wherever they fit, never niche, regional, dated or
offensive terms, and never force slang in. Keep abbreviations in their normal written form.
Respond with ONLY a JSON array. Each element has exactly:
  "sentence":  the English sentence (5-14 words, complete, natural contractions)
  "meaning":   normally a simple English paraphrase, at most 10 words, never a
               translation. If the sentence contains slang, an idiom or an
               abbreviation, use up to 35 words to explain it: full form or
               literal words, plain-English meaning, and how it is actually
               said. Give a pronunciation only where the spoken form differs
               from the written one: some initialisms are read as letters
               (FYI is said "eff-why-eye"), a few as a word (ASAP is said
               "ay-sap", not "A-S-A-P"), and many chat abbreviations are
               spoken as the full words they stand for rather than read letter
               by letter — give that full form instead of inventing a
               letter-by-letter reading
  "situation": one short English line describing when a native speaker says it
No markdown, no code fences, no commentary.
```

User instruction includes:

- the topic title and description (description may be blank),
- the learner's CEFR level from `getLearningProfile` (`AUTO` → infer),
- the requested count (1 / 5 / 10),
- the existing sentences of that topic (up to 50, one per line) with an explicit
  instruction not to repeat or lightly reword any of them,
- the quality bar: high-frequency real-life spoken English, no literary or textbook
  register, slang/idioms/abbreviations encouraged where natural, any slang explained
  in full inside `meaning`, no proper nouns that need outside context, no two
  candidates alike, vary the sentence structures.

Parsing (`parseGeneratedSentences`):

- tolerate code fences and surrounding prose by extracting the first JSON array,
- drop entries with an empty `sentence` or empty `meaning`,
- default a missing/invalid `situation` to `''`,
- drop duplicates against the existing set and within the batch,
- only zero valid candidates is fatal (`OpenRouterResponseError`).

## 2.6 Practice cards

`practiceMode` preference (`'auto' | 'dictation' | 'recall'`, default `auto`), stored
exactly like `preferences/grammarCheck.ts`.

| Mode | Card |
| --- | --- |
| `auto` | `new`/`learning` → dictation; `review` → recall |
| `dictation` | every card is dictation |
| `recall` | every card is recall |

**Dictation card**

- The sentence is spoken once automatically on card open, with a replay button.
- The learner types what they heard into a `TextInput`.
- `Check` normalizes both sides, shows a word-level diff (correct / missing / extra /
  substituted), and pre-selects the suggested grade.
- Suggested grade: an exact normalized match, or a single token that differs by one
  typo-sized edit, → `Good`; anything else → `Again`.
- The learner may tap any of Again / Hard / Good / Easy regardless of the suggestion.

**Recall card**

- Shows the `situation`, with a "Show meaning" hint that reveals the English `meaning`.
- The learner produces the sentence (aloud or in their head), then reveals the answer.
- Revealing plays the TTS and shows the English sentence, then the grade buttons.

Both cards: one active TTS playback at a time, silence on unmount and on card change,
speech settings respected (same contract as `ChatScreen` / `SampleConversationModal`).

## 2.7 Mode gating

The feature is serverless-only, enforced like every other mode-specific feature:

1. **Home row** is hidden in server mode (mirroring how the Settings vocabulary row is
   hidden in serverless mode).
2. **Screen guard**: the topics screen renders an explicit serverless-only notice in
   server mode, waits for the persisted mode to be restored, and reads nothing from the
   database in that state.
3. `clearAllServerlessData()` clears the three new tables.
4. `docs/MODE_CAPABILITY_MATRIX.md` gains the new rows.

# 3. Global rules

## Rule 1 — Serverless only, no backend changes

Do not modify anything under `backend/`. Do not add endpoints. Serverless provider
requests continue to go directly from the mobile app to the configured provider.

## Rule 2 — Preserve the two application modes

Server mode behavior is unchanged except that the new Home row is hidden there. The
runtime gate (`assertServerApiAllowed`) is untouched — this feature never calls the
backend, in either mode.

## Rule 3 — Tests accompany implementation

Every task adds or updates Jest tests. Mobile tests run without a device; database
tests use the in-memory `sql.js` driver already wired in `mobile/__tests__`; AI calls
are exercised through injected `complete` seams, never real HTTP.

## Rule 4 — Style

- Strict TypeScript, explicit types, no `any`.
- Single quotes, no semicolons, 2-space indentation (existing Prettier config).
- JSDoc block at the top of every new module explaining its responsibility.
- `pnpm lint`, `pnpm typecheck` and `pnpm test` must pass at the end of every task.

## Rule 5 — No secrets, no new permissions

Never log or persist provider keys. The keychain usage stays exactly as it is now.

## Rule 6 — No Vietnamese

No Vietnamese string is added anywhere in this feature. Meaning and situation are
English.

# 5. Completion condition

The feature is complete when a learner can:

1. See an icon next to every Home row.
2. Open Real-life sentences and create a topic with a description.
3. Generate 1, 5 or 10 sentences, keep all or a selection, and see them persisted.
4. Play any sentence with TTS and delete sentences that are not useful.
5. Open Practice once the topic holds 5 sentences and get only the due cards.
6. Type a dictated new sentence and be graded (with an overridable suggestion).
7. Recall a review sentence from its situation and grade it Again / Hard / Good / Easy.
8. See the same sentence come back later each time it is answered well, and come back
   in ten minutes when it is forgotten.
9. Close and reopen the app and keep every topic, sentence and schedule.
10. Use all of it in serverless mode only, with no Django backend change.
